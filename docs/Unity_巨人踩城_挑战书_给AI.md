## 先说清楚：为什么这份挑战书存在

之前有一版（网页 Babylon 那条线）被用户判了死刑，原话是"**根本玩不了、什么都看不见、移动不了、建模粗糙得像一堆盒子**"。
那一版的失败不是功能少，而是**底层没成型**：尺度没定、相机是错的、输入没接通、城市是占位。

现在换到 Unity。**坑不会变少，只会换名字。** 下面这 5 条，是 Unity 版最容易死的地方——每一条我都在 UMT 源码里找到了确切位置，不是吓唬你。

## 五条硬骨头

**① 尺度：PMX 进 Unity 就是 1.6 m（真人高），"巨人"必须靠缩世界伪造。**
`MMDConstants.k_MMDUnitToUnityUnit = 0.08`。你敢缩放巨人 root，Bullet 的弹簧参数就脱离标定区间（源码注释里写着它是按 Unity 米制标定的）→ **裙子头发当场乱飞**。
做法：巨人 `localScale` 永远 1；把城市+小人放进 `WorldRoot` 统一缩小（≈0.05）。
**跟着必须改的**：相机 `nearClipPlane`（默认 0.3 → 不调就是"什么都看不见"）、`Physics.gravity`、`CharacterController.skinWidth/minMoveDistance`、阴影距离、粒子与音效距离。漏一个就出一个玄学 bug。

**② 移动不了：`CharacterController.minMoveDistance` 默认 1 mm ≈ 你缩小世界后每帧的全部位移。**
控制器会判定"移动量太小"直接丢弃 → 原地抖。
再加上输入系统的老坑：`Active Input Handling` 设成 New 却用 `Input.GetAxis` 会**抛异常**，症状同样是"按了没反应"。
排查顺序写好了，照做，别瞎试。

**③ 时序：骨骼的最终位置由 `MMDTransformManager` 在 `[DefaultExecutionOrder(10000)]` 的 `LateUpdate` 里写回。**
你的踩踏判定、贴花、相机跟随**都必须排在它之后**，否则永远慢半拍。

**④ 物理的真相：Bullet 的地面是"一个无限平面"，不是 Collider。**
给楼加 Collider 挡不住裙摆。而且原生库只有 Windows x64 / Android arm64 / Web 三份——**Android 必须只勾 ARM64**，否则真机直接缺库。
（macOS/Linux 编辑器没有物理，那是预期，要优雅降级，不是 bug。）

**⑤ 内容：只做一个"被追着踩、活 60 秒"的循环，用户两分钟就腻。**
需求与制作文档里给了 P0/P1/P2 全套（4 种模式、分区城市、藏身潜行、她的性格与动作库、换鞋、连锁破坏、爬上她、慢动作特写）。
**但别一口气全铺开**——先 P0 做扎实，再逐项加，每项都要能单独截图演示。

> **明确不做**：道具/消耗品（烟雾弹、护盾、加速、诱饵…）、技能树、数值成长、每日任务、联机；以及**已被否决**的五个点子：脚趾缝藏身、落地风压、踩扁弹回、胆子计分、震动分级。
